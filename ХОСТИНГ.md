# Размещение сайта

| Что | Где | Цена |
|---|---|---|
| Код | GitHub, публичный репозиторий | 0 ₸ |
| **samnaz.group** — сам сайт | GitHub Pages | 0 ₸ |
| **samnaz.kz** — редирект на .group | DNS-хостинг hoster.kz | 0 ₸ |
| Заявки | Telegram напрямую из браузера | 0 ₸ |

Бэкенда нет вообще: сайт статический, форма стучится в Telegram из браузера
посетителя. Держать нечего — значит и платить не за что. Оба домена оплачены
на 10 лет вперёд, всё остальное продлевается само и бесплатно.

---

## Шаг 1. Репозиторий на GitHub

Git настроен, коммиты сделаны. Осталось создать удалённый репозиторий и залить.
Одна команда:

```bash
gh auth login && gh repo create samnaz-site --public --source=. --push
```

Без `gh`: создать на <https://github.com/new> репозиторий `samnaz-site`,
**Public**, README и .gitignore **не** добавлять, затем:

```bash
git remote add origin https://github.com/ТВОЙ_ЛОГИН/samnaz-site.git && git push -u origin main
```

Пароль от GitHub при пуше не подойдёт — нужен токен: Settings → Developer
settings → Personal access tokens → **Tokens (classic)** → Generate new token →
галочка `repo` → Expiration **No expiration**.

---

## Шаг 2. Включить GitHub Pages

Репозиторий → **Settings** → слева **Pages**:

* Source — **Deploy from a branch**
* Branch — **main**, папка — **`/ (root)`**
* Save

Через пару минут сайт живёт на `https://ТВОЙ_ЛОГИН.github.io/samnaz-site/`.

В репозитории уже лежат два служебных файла, ничего добавлять не нужно:
`.nojekyll` (чтобы GitHub отдавал файлы как есть, не пытаясь собрать блог)
и `CNAME` (адрес основного домена).

---

## Шаг 3. Домен samnaz.group

Namecheap → Domain List → `samnaz.group` → **Manage** → **Advanced DNS**.

Удалить всё, что там стоит по умолчанию (парковочная страница), и добавить:

| Тип | Host | Значение |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| AAAA | `@` | `2606:50c0:8000::153` |
| AAAA | `@` | `2606:50c0:8001::153` |
| AAAA | `@` | `2606:50c0:8002::153` |
| AAAA | `@` | `2606:50c0:8003::153` |
| CNAME | `www` | `ТВОЙ_ЛОГИН.github.io.` |

Четыре A-записи — не дубли и не ошибка: это резервирование, GitHub так
и требует. AAAA нужны для посетителей на IPv6; без них тоже работает,
но лучше поставить.

Дальше: Settings → Pages → **Custom domain** → вписать `samnaz.group` → Save.
Подождать, пока пройдёт проверка (от 15 минут до суток), затем поставить
галочку **Enforce HTTPS**. Сертификат GitHub выпустит и будет продлевать сам.

## Шаг 4. samnaz.kz → редирект на samnaz.group

Тут есть ловушка, из-за которой нельзя просто повесить `.kz` на GitHub.

**Правила зоны `.kz` требуют казахстанский IP.** Если A-запись `samnaz.kz`
смотрит на иностранный сервер (а GitHub — иностранный), приходит
предупреждение, даётся 10 дней, потом домен приостанавливают, ещё 10 дней —
удаляют из реестра. Оплата на 10 лет вперёд от этого не спасает: удаляют
за нарушение правил, а не за неуплату.

Решение бесплатное и полностью законное: редирект делает **сам hoster.kz**
на своём казахстанском сервере. Домен смотрит на IP в Казахстане — правила
соблюдены; посетитель мгновенно улетает на `samnaz.group`.

### Настройка

1. Личный кабинет hoster.kz → **Домены** → `samnaz.kz`.
2. Проверить NS — должны стоять их: `ns1.hoster.kz`, `ns2.hoster.kz`,
   `ns3.hoster.kz`. Без этого редирект не заработает.
3. Включить переключатель **DNS-хостинг**, если он выключен.
4. A-записи `samnaz.kz` и `www.samnaz.kz` → **`89.35.125.9`**
   (это редирект-сервер hoster.kz).
5. Включить опцию **«Редирект на домене»**:
   * тип — **301** (постоянный: браузеры запоминают, поисковики склеивают
     вес доменов и не считают это дублем);
   * целевой URL — `https://samnaz.group`.
6. Проверить через 10–20 минут.

### Обязательно проверь HTTPS

Открой именно **`https://samnaz.kz`**, не `http://`. Два исхода:

* **Открылось и перебросило** — готово, дальше ничего не делай.
* **Ошибка сертификата** — на редирект-сервере нет SSL для твоего домена.
  Написать в поддержку hoster.kz: *«Прошу выпустить бесплатный Let's Encrypt
  на домен samnaz.kz, используется ваш сервис редиректа»*. Обычно включают
  бесплатно. Если откажут — самый дешёвый тариф Economy-1 (~500 ₸/мес),
  там Let's Encrypt точно есть. Это единственное место во всей схеме,
  где теоретически могут появиться расходы.

Без рабочего HTTPS домен тоже могут заблокировать — это отдельный пункт
правил зоны, поэтому шаг не пропускай.

### Проверка на соответствие правилам

<https://rules.hoster.kz/?domain=samnaz.kz> — должно быть зелено:
казахстанский IP, живой SSL, корректный WHOIS.

## Как вносить изменения

```bash
git add -A && git commit -m "что поменял" && git push
```

Через 1–2 минуты обновилось на `samnaz.group`.

**Важно:** правя `main.css` или `main.js`, поднимай номер в `?v=` у ссылок
в HTML — иначе у тех, кто уже был на сайте, останется старая версия
из кэша. Сейчас везде `v=23`, значит следующая правка — `v=24`.
Заменить во всех файлах разом:

```bash
sed -i '' 's/?v=23/?v=24/g' *.html
```

## Лимиты GitHub Pages

Сайт — 132 файла и 28 МБ, вписываемся с огромным запасом.

* размер сайта — до 1 ГБ
* трафик — 100 ГБ в месяц (это десятки тысяч посетителей)
* сборок — до 10 в час
* сайт должен быть публичным (или платный тариф)

Ограничение из правил: GitHub Pages нельзя использовать как площадку
для интернет-магазина и онлайн-транзакций. Сайт-визитка строительной
компании под это не попадает — мы ничего не продаём онлайн, только
рассказываем об услугах и принимаем заявки.

## Что нужно продлевать

Домены оплачены на 10 лет — это, собственно, всё. GitHub Pages и SSL
продлеваются автоматически и бесплатно.

Одна просьба: включи **автопродление** на обоих доменах (hoster.kz
и Namecheap) и держи на привязанной карте живой баланс. Сайты почти
никогда не умирают от поломок — они умирают от забытого продления домена.

## Про токен Телеграм-бота и публичный репозиторий

Репозиторий теперь публичный, и токен в `assets/js/vendor/metrics.js`
виден всем. Три вещи, которые надо понимать честно:

1. **Хуже, чем было, почти не стало.** Сайт и так публичный: файл отдаётся
   вместе со страницей любому посетителю, base64 разворачивается за секунду.
   Приватный репозиторий эту дыру не закрывал.
2. **Чем это грозит.** Если токен утащат, чужой человек сможет писать
   от имени бота и читать входящие заявки. Деньги и данные клиентов
   этим не достать, но неприятно.
3. **GitHub умеет сам отзывать токены.** Секретный сканер ищет ключи
   в публичных репозиториях и сообщает Telegram, а тот токен отключает.
   Наш записан в base64, поэтому под шаблон, скорее всего, не попадёт —
   но если однажды бот молча перестанет отвечать, причина, вероятно, эта.
   Лечится за минуту: `/revoke` у @BotFather, новый токен в тот же файл.

Закрывается по-настоящему в любой момент: в папке `bot/` лежит готовый
Cloudflare Worker. Бесплатно, 10 минут, токен уезжает в серверный секрет,
в сайте остаётся только адрес эндпоинта. Подробности — в `ТЕЛЕГРАМ-БОТ.md`.
